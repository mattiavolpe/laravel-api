## 2024-04-24 - Implicit Route Model Binding IDOR Vulnerability
**Vulnerability:** Insecure Direct Object Reference (IDOR) due to missing authorization checks when using implicit route model binding. Controllers `show`, `edit`, `update`, and `destroy` methods were relying on implicit model binding without validating if the authenticated user actually owns the retrieved model. This allowed an attacker to access, modify, or delete resources belonging to other users simply by changing the ID in the URL.
**Learning:** Laravel's route model binding automatically retrieves models from the database based on route parameters. However, it does not inherently apply ownership checks unless scoped queries or policies are used. The lack of `Policies` meant controllers needed explicit ownership verification. Using strict comparison (`!==`) when comparing Eloquent model IDs with `auth()->id()` can cause false-positive 403s due to type casting differences (e.g., string from DB vs integer from auth).
**Prevention:** Always implement explicit authorization checks (e.g., `if ($model->user_id != auth()->id()) abort(403);`) within controller methods that handle implicitly bound models if no Laravel Policy is defined. Use loose comparison (`!=`) to avoid type mismatch issues. Alternatively, implement and utilize Laravel Policies (`$this->authorize('view', $model)`) or scoped bindings (`->scopeBindings()`) in routes to enforce consistent access control.
