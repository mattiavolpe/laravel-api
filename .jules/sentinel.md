## 2024-05-02 - IDOR in Implicit Route Model Binding

**Vulnerability:** Insecure Direct Object Reference (IDOR) vulnerabilities exist across `ProjectController`, `TypeController`, and `TechnologyController`. The controllers use implicit route model binding (e.g., `public function show(Project $project)`) to retrieve user-owned resources, but fail to implement explicit authorization checks in the `show`, `edit`, `update`, and `destroy` methods. This allows any authenticated user to view, edit, or delete resources belonging to other users simply by changing the resource ID/slug in the URL.

**Learning:** When Laravel Policies are not implemented, relying solely on implicit route model binding without controller-level ownership checks exposes applications to critical IDOR vulnerabilities. `Type` and `Technology` models, despite behaving like global taxonomies in many apps, are user-owned in this architecture (indicated by `$fillable` `user_id` and the `store` method logic) and require the same protection as the primary `Project` entity. Due to type mismatches between string database IDs and integer `auth()->id()`, strict comparison (`!==`) often leads to false-positive 403s; loose comparison (`!=`) is required. Using the global helper `auth()->id()` avoids fatal errors from missing facade imports.

**Prevention:** Always verify ownership of resources retrieved via implicit route model binding. Implement explicit ownership checks (`if ($model->user_id != auth()->id()) abort(403);`) within each relevant controller method, or prefer implementing and using Laravel Policies to centralize authorization logic.
