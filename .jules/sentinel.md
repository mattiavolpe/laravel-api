## 2024-05-18 - Missing Authorization Checks Lead to IDOR in User-Owned Models
**Vulnerability:** Found multiple Insecure Direct Object Reference (IDOR) vulnerabilities in the Admin controllers (`ProjectController`, `TypeController`, `TechnologyController`). Implicit route model binding was fetching records successfully without verifying if the currently authenticated user owned them, allowing any logged-in user to view, edit, or delete another user's `Project`, `Type`, or `Technology` models by manipulating the model ID in the URL.
**Learning:** The application architecture relies on implicit route model binding but doesn't universally employ Laravel Policies for user-owned models like `Type` and `Technology` (which are indeed user-specific, defined by their `$fillable` `user_id` and assigned via `Auth::id()` on creation). This pattern requires explicit ownership checks at the controller level. Furthermore, when comparing Eloquent model properties (e.g., `$model->user_id`) against `auth()->id()`, strict comparison (`!==`) can lead to false-positive 403 errors due to PHP typing discrepancies (string vs. integer casting from the DB), making loose comparison (`!=`) the reliable approach for these checks.
**Prevention:** Always verify ownership constraints (e.g., `if ($model->user_id != auth()->id()) abort(403);`) on all `show`, `edit`, `update`, and `destroy` methods when dealing with user-owned models, or implement comprehensive Laravel Policies that enforce these checks globally.
