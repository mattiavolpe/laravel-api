## 2024-05-24 - Fix IDOR vulnerabilities in Admin controllers
**Vulnerability:** Insecure Direct Object Reference (IDOR) vulnerabilities were present in the `ProjectController`, `TypeController`, and `TechnologyController` within the `app/Http/Controllers/Admin` directory. The models are user-owned entities (indicated by `user_id`), but the controllers lacked explicit ownership checks in the `show`, `edit`, `update`, and `destroy` methods, allowing any authenticated user to view, edit, update, or delete other users' models via implicit route model binding.
**Learning:** The application utilizes implicit route model binding in controllers without implementing Laravel Policies. This architectural pattern makes the application susceptible to IDOR vulnerabilities because it automatically retrieves records based on the route parameter without validating if the current user owns them.
**Prevention:** Always enforce explicit ownership checks (e.g., `if ($model->user_id != auth()->id()) abort(403);`) in controller methods (like `show`, `edit`, `update`, `destroy`) when models are user-owned and Laravel Policies are not implemented. Use loose comparison (`!=`) instead of strict comparison (`!==`) to prevent false-positive 403 errors caused by type mismatches (e.g., string vs. integer casting from the database).
