## 2024-05-14 - IDOR Vulnerabilities in Admin Controllers
**Vulnerability:** Implicit route model binding was used in admin controllers (`ProjectController`, `TechnologyController`, `TypeController`) without Laravel Policies or explicit ownership checks. This allowed any authenticated user to read, modify, or delete entities belonging to other users simply by changing the ID in the URL.
**Learning:** In this application architecture, models like `Project`, `Type`, and `Technology` are user-owned entities, not global resources. However, the use of implicit route model binding (e.g., `public function show(Project $project)`) automatically retrieves the model based on the URL parameter *without* checking if it belongs to the currently authenticated user.
**Prevention:** Always add explicit ownership checks (e.g., `if ($model->user_id !== auth()->id()) abort(403);`) within controller methods that use route model binding, or implement Laravel Policies to enforce authorization rules globally. Note: prefer `auth()->id()` over `Auth::id()` to avoid 'Class not found' errors if the Facade is not imported.
