## 2024-05-06 - Insecure Direct Object Reference (IDOR) in Admin Controllers
**Vulnerability:** The codebase uses implicit route model binding in controllers (e.g., `Admin/ProjectController`, `TypeController`, `TechnologyController`) without implementing Laravel Policies. This architectural pattern allows users to access, edit, or delete entities belonging to other users.
**Learning:** In this application, `Type` and `Technology` models are user-owned entities, not global taxonomies. When fixing IDOR vulnerabilities by manually enforcing ownership checks in the controller methods (e.g., `if ($model->user_id != auth()->id()) abort(403);`), loose comparison (`!=`) must be used instead of strict comparison (`!==`) to prevent false-positive 403 errors caused by type mismatches between the database string/integer and the authenticated user's ID. Also, prefer the global helper `auth()->id()` over the `Auth::id()` facade to avoid 'Class not found' errors.
**Prevention:** Explicitly enforce ownership checks in controller methods utilizing implicit route model binding. If possible, transition to using Laravel Policies for centralized authorization management.
