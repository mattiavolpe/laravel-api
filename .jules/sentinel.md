## 2024-05-03 - Insecure Direct Object Reference (IDOR) via Implicit Route Model Binding in Laravel Controllers
**Vulnerability:** Controller methods (like `show`, `edit`, `update`, `destroy` in `ProjectController`, `TypeController`, `TechnologyController`) use implicit route model binding to inject Eloquent models, but lack explicit authorization checks to ensure the currently authenticated user actually owns the retrieved model. This allows any authenticated user to access, modify, or delete records belonging to other users simply by changing the ID or slug in the URL.
**Learning:** Laravel's route model binding retrieves the model regardless of ownership. If Laravel Policies are not implemented, authorization must be explicitly handled in the controller. Furthermore, when comparing model IDs with the authenticated user ID (`auth()->id()`), loose comparison (`!=`) must be used instead of strict comparison (`!==`) to avoid false-positive 403 errors due to type mismatch (e.g., string from the database vs. integer from the auth layer).
**Prevention:** Always verify ownership for user-owned models using `if ($model->user_id != auth()->id()) abort(403);` in the relevant controller methods, or implement and use Laravel Policies for authorization.
