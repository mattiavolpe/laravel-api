## 2024-04-06 - Insecure Direct Object Reference (IDOR) via Implicit Route Model Binding
**Vulnerability:** Admin controllers (`ProjectController`, `TypeController`, `TechnologyController`) used implicit route model binding to fetch records based on route parameters, but failed to verify that the currently authenticated user actually owned the fetched record before returning it or modifying it in `show`, `edit`, `update`, and `destroy` methods. This allowed any authenticated user to view, edit, or delete records belonging to other users simply by changing the ID in the URL.
**Learning:** In Laravel, implicit route model binding automatically retrieves a model instance based on a route segment. However, it only ensures the record exists in the database, not that the user is authorized to access it. When standard Laravel Policies are not implemented to handle these checks automatically, explicit ownership checks must be manually enforced in the controller methods for every action that handles a specific model instance.
**Prevention:** Always verify ownership (`if ($model->user_id !== auth()->id()) abort(403);`) or implement Laravel Policies for controller methods that accept implicitly bound models to ensure users can only access or modify their own resources. Avoid relying solely on Eloquent relationships in index methods for security, as those do not protect specific item routes.
