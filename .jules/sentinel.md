## 2025-04-17 - Missing IDOR Authorization Checks in Route Model Binding
**Vulnerability:** The `ProjectController`, `TypeController`, and `TechnologyController` methods (`show`, `edit`, `update`, `destroy`) used implicit route model binding to fetch records, but lacked explicit authorization checks. This allowed any authenticated user to pass another user's model ID and view, edit, or delete records they do not own (Insecure Direct Object Reference).
**Learning:** In applications without Laravel Policies implemented, utilizing implicit route model binding leaves endpoints vulnerable to IDOR unless manual checks are strictly enforced in every resource method. Additionally, it is critical to use loose comparison (`!=`) instead of strict comparison (`!==`) when comparing Eloquent model IDs with `auth()->id()` to avoid false-positive authorization failures.
**Prevention:** Always implement explicit ownership checks (e.g., `if ($model->user_id != auth()->id()) abort(403);`) within the controller methods that manipulate user-owned entities, or use explicit Laravel Policies instead.
