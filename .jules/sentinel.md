## 2024-03-28 - [HIGH] Fix Authorization Bypass in Controllers
**Vulnerability:** Authorization Bypass (Insecure Direct Object Reference) in `ProjectController`, `TypeController`, and `TechnologyController`. Authenticated users could access, modify, and delete resources belonging to other users simply by changing the ID in the URL.
**Learning:** This happened because while Route Model Binding loads the model from the database based on the URL parameter, it does not automatically check if the currently authenticated user owns that model. In a multi-tenant or multi-user application, simply relying on the `auth` middleware is not enough to protect specific resources from other authenticated users.
**Prevention:** Always verify authorization *after* authentication for any operation that interacts with specific resources. Add explicit ownership checks like `if ($model->user_id !== Auth::id()) { abort(403); }` in controller methods, or use Laravel's Authorization features like Policies or Gates to ensure users can only interact with their own data.
