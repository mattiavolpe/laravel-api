## 2026-03-26 - Missing Input Validation in ContactController
**Vulnerability:** The `ContactController@store` method used `$request->all()` to fill a new `Contact` model directly. This completely bypassed input validation, allowing any data to be processed. While the `Contact` model has `$fillable` attributes to prevent mass assignment of unexpected fields, the lack of length limits on accepted fields exposed the application to potential Denial of Service (DoS) and spam risks, and the lack of type/format validation meant invalid email addresses or unexpected data types could be passed to the `NewContact` mailer.
**Learning:** Even with Eloquent's mass assignment protection (`$fillable`), relying on `$request->all()` is a bad practice for external input because it bypasses basic data sanitization and length constraints, which are critical defense-in-depth measures against resource exhaustion and data corruption.
**Prevention:** Always use `$request->validate()` to explicitly define expected fields, their types, formats (like `email`), and length constraints (`max:255`, `max:5000`). This ensures that only sanitized, expected data enters the application flow.
