## 2026-06-13 - IDOR Vulnerabilities in ProjectController
**Vulnerability:** The `show`, `edit`, `update`, and `destroy` methods in `app/Http/Controllers/Admin/ProjectController.php` lacked authorization checks to verify if the currently authenticated user owned the project being accessed or modified. This allowed Insecure Direct Object Reference (IDOR) attacks.
**Learning:** Implicit route model binding in controllers does not automatically scope the retrieved model to the authenticated user. Without Laravel Policies or explicit checks in the controller, any user could potentially view, edit, or delete projects belonging to other users if they know or guess the project ID/slug.
**Prevention:** Always implement explicit ownership checks (e.g., `if ($project->user_id != auth()->id()) abort(403);`) in controller methods that handle user-specific resources, or utilize Laravel Policies for more robust authorization management. Avoid strict comparisons (`!==`) when comparing user IDs to prevent false positives due to type mismatch.
