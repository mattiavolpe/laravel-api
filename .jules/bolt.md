## 2024-05-07 - Eloquent Memory Optimization with Aggregates
**Learning:** Loading entire relationships into memory (e.g., `Auth::user()->projects()->get()`) just to calculate counts or find the first/last records leads to an O(n) memory footprint in PHP. In Laravel, chaining methods like `latest()` onto an Eloquent relationship modifies a shared query builder instance, which can cause side effects across queries if not handled carefully.
**Action:** Use database-level aggregates like `->count()` and query builder methods like `->latest()->first()` to shift the computation workload to the database (O(1) memory). When executing multiple aggregate queries on the same relationship method (e.g., `Auth::user()->projects()`), assign the base relationship query builder to a variable and explicitly `clone` it for each subsequent query to avoid cross-query pollution.
