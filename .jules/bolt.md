## 2026-04-18 - Inefficient Collection Hydration for Database Aggregates
**Learning:** Checking record existence using `count(Model::where(...)->get()->toArray())` or counting all relations via `$model->relation()->get()` and then calling `count()` on the PHP array/collection is extremely inefficient. It loads all matching records into PHP memory, causing significant CPU and memory bloat on large datasets when only a single integer value or boolean check is needed. This is a common anti-pattern in Laravel controllers.
**Action:** Always prefer database-level execution methods like `->exists()` for boolean checks and `->count()` on the query builder (`Model::where(...)->count()`) to perform aggregations efficiently at the database level. For dashboard-like views needing specific items from a large relation, fetch them individually using `->first()` with the correct order instead of loading the entire relation collection.
