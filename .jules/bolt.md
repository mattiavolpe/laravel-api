## 2024-05-18 - Optimized relationship counts to eliminate N+1 query problem
**Learning:** Laravel's eager loading is vital, especially when dealing with nested resources. Specifically, using `$model->projects()->withCount('projects')` allows us to compute `projects_count` entirely at the database layer instead of instantiating all related project models into memory just to run `count()` on them in Blade views, solving severe N+1 memory issues. Also, remember to not accidentally update unrelated `composer.json` or `package.json` lock files or modify unrelated files to force tests to pass unless absolutely necessary for the actual feature ticket.
**Action:** When passing a list of eloquent models that only require counting a relationship on a view layer, always use `withCount('relationship_name')` in the controller query instead of executing `count($model->relationship_name)` in the template. This creates a much lighter SQL footprint. Keep commits focused only on intended codebase parts.
