## 2024-03-27 - [Prevent In-Memory Aggregation for O(1) Memory Footprint]
**Learning:** The application heavily used in-memory aggregations via `count($models)` after eagerly fetching all relational models via `get()` or using `->toArray()` on entire collections to just check for existence during `create` or `update` (`count(Model::where(...)->get()->toArray()) > 0`). This caused unnecessary hydration of models, leading to excessive PHP memory usage scaling with the total number of projects, which could crash the request for users with thousands of entries.
**Action:** Always favor database-level aggregation functions (`->count()`, `->exists()`, `->latest()->first()`) when the full collection is not needed to reduce load on the PHP thread and perform O(1) memory processing. When updating, use `->where('id', '!=', $model->id)->exists()` instead of loading collections and counting array keys.
